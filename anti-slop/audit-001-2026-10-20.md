# Antislop Audit Report #001

**Date:** 2026-10-20  
**Project:** Signature Studio (`magical-fermi`)  
**Audited Targets:** `index.html`, `css/studio.css`, `css/theme.css`, `email-signature.html`, `cards/*/email-signature.html`, `js/studio.js`, `js/studio-templates.js`  
**Reference:** `antislop.md` (v3.2.x, Rules R-01 to R-38)

---

## Executive Summary

The codebase has strong functional foundations (accessible forms, local storage persistence, responsive table calculations, live contrast checking). However, an audit against `antislop.md` identifies **16 specific violations** spanning:
- **Hard Gate (HIGH)**: 7 violations (forbidden em dash, broken navigation routing on sub-views, WCAG AA contrast failure on step numbers, sub-44px touch targets on mobile, dead CSS override bloat, incomplete dark toggle state, missing live empty state).
- **Purpose-Gate (MEDIUM)**: 5 violations (excessive glassmorphism across 4+ surfaces, 60px colored glow shadows, default arrow icons on all CTAs, dark purple base64 email backgrounds, distracting infinite focus pulse).
- **Quality Locks (LOW)**: 4 violations (classic AI template tropes: fake 3-dot window bar, formulaic 3-step numbered workflow, pill-radius inconsistencies, missing `DESIGN.md` / dials).

---

## Numbered Findings List

### HIGH Priority — Hard Gate (Absolute Violations)

1. **[R-02] Forbidden Em Dash in Document Title**
   - **Location:** `index.html:L7`
   - **Reason:** Uses forbidden em dash character (`—`) in `<title>Signature Studio — professional email signatures</title>`.
   - **Recommended Fix:** Replace with a colon or hyphen: `Signature Studio: Professional Email Signatures`.

2. **[R-24 / R-26] Broken Navigation from App Views to Home**
   - **Location:** `index.html:L18, L20` & `js/studio.js:L152`
   - **Reason:** Neither `<a class="brand" href="#home">` nor `<a href="#how-it-works">How it works</a>` have `data-view="home"`. When on Studio or Gallery view, clicking them leaves `#home-view` hidden, resulting in dead/unresponsive controls.
   - **Recommended Fix:** Add `data-view="home"` to the brand link and attach click handling to switch views before scrolling to anchor targets.

3. **[R-25] WCAG AA Color Contrast Failure on Step Indicators**
   - **Location:** `css/studio.css:L27`
   - **Reason:** `.step-number` uses `#94a3b8` on `#ffffff` (contrast ratio **2.56:1**), failing the mandatory 4.5:1 minimum for normal text (13px).
   - **Recommended Fix:** Darken to `#475569` (contrast ratio **5.66:1**) or `--muted` to guarantee WCAG AA compliance.

4. **[R-03] Mobile Touch Targets Under Minimum 44px**
   - **Location:** `css/studio.css:L24, L28`
   - **Reason:** `.btn-remove-item` is sized at `38px x 38px` and `.button-small` has `min-height: 38px`, failing the required 44px minimum tap target on touchscreens.
   - **Recommended Fix:** Increase `.btn-remove-item` to `min-width: 44px; min-height: 44px` and set small buttons to `min-height: 44px` on mobile `@media (max-width: 680px)`.

5. **[R-33] CSS Patching & Dead Keyframe/Blob Bloat**
   - **Location:** `css/theme.css:L150-237` vs `L748`
   - **Reason:** Lines 150-237 define 87 lines of morphing radial gradient blobs (`@keyframes blobMorph`), only for line 748 to slap `.hero-glass::before, .hero-glass::after { display: none; }` at the bottom of the file.
   - **Recommended Fix:** Cleanly delete the dead blob pseudo-elements and keyframes from the source stylesheet instead of overriding with append-patches.

6. **[R-34] Incomplete Dark Theme Toggle Semantics**
   - **Location:** `index.html:L19` & `js/studio.js:L175-186`
   - **Reason:** Button displays a static emoji `🌓` and static `aria-label="Toggle dark mode"` with no `aria-pressed` state or visual indication of active theme.
   - **Recommended Fix:** Use proper Material Symbols / SVG icon (`dark_mode` / `light_mode`), update `aria-pressed="true|false"` dynamically, and provide explicit tooltips.

7. **[R-27] Missing Graceful Empty State for Signature Canvas**
   - **Location:** `js/studio-templates.js` & `index.html:L41, L55`
   - **Reason:** When all fields are cleared, the preview renders an awkward partially empty table rather than a dedicated, crafted empty state prompting user action.
   - **Recommended Fix:** Implement an explicit empty state placeholder when `fullName` and primary fields are blank.

### MEDIUM Priority — Purpose-Gate (Technique Without Stated Purpose)

8. **[R-10] Excessive Glassmorphism Dose Cap Exceeded**
   - **Location:** `css/studio.css:L28, L35` & `css/theme.css:L34, L433, L545, L687`
   - **Reason:** `backdrop-filter: blur(...)` is applied simultaneously to `.site-header`, `.hero-preview`, `.control-section`, and `.glass-panel`, exceeding the 1-2 element dose cap.
   - **Recommended Fix:** Keep blur strictly on `.site-header` as a subtle floating accent; use clean, crisp opaque/semi-opaque surface fills for cards and sidebar controls.

9. **[R-13] Heavy 60px Colored Glow Shadows**
   - **Location:** `css/theme.css:L702` & `email-signature.html:L98`
   - **Reason:** `.dark-mode .hero-preview` has `box-shadow: ... 0 0 60px -10px hsl(235 85% 58% / 0.35);` (AI colored orb glow), and buttons have `rgba(255, 82, 82, 0.4)` glow.
   - **Recommended Fix:** Replace diffuse colored glows with clean, natural ambient elevation shadows (`rgba(0, 0, 0, 0.25)`).

10. **[R-08] Default Arrow Glyphs on Every Action Button**
    - **Location:** `index.html:L20, L30, L57` & `js/studio.js:L136`
    - **Reason:** Every primary button automatically appends `arrow_forward` (`→`) regardless of action (e.g. "Create a signature →", "Start creating →", "Open editor →", "Use template →").
    - **Recommended Fix:** Reserve directional arrows strictly for sequential next-step navigation; remove redundant arrows from standard triggers.

11. **[R-01] Fragile Base64 Backgrounds & Default AI Dark Palettes**
    - **Location:** `email-signature.html:L5`, `cards/*/email-signature.html`, `js/studio-templates.js:L20, L48`
    - **Reason:** Giant 20-ring base64 radial SVG patterns are embedded in email tables (which get stripped or ignored by Outlook/Word engines). In presets, palettes lean into cliché dark neon/purple AI schemes (`cosmic-blue`, `royal-indigo`).
    - **Recommended Fix:** Use email-safe solid colors or subtle linear gradients with solid MSO fallbacks, and balance presets with refined, editorial palettes.

12. **[R-19] Distracting Infinite Focus Pulsing**
    - **Location:** `css/theme.css:L366-375`
    - **Reason:** Defines `animation: focusPulse 1s infinite;` on interactive focus. Infinite pulsing animations distract keyboard users and fail calm usability standards.
    - **Recommended Fix:** Remove `focusPulse` and enforce a static, crisp 3px high-contrast focus outline (`:focus-visible { outline: 3px solid var(--blue); outline-offset: 2px; }`).

### LOW Priority — Quality Locks & AI Archetypes

13. **[R-05] Formulaic 3-Step Section & Fake macOS Window Chrome**
    - **Location:** `index.html:L40, L44`
    - **Reason:** Features the stereotypical AI landing page elements: fake macOS 3-dot window bar (`preview-window-bar`) and an exact 3-step "How it works" section with circular step badges.
    - **Recommended Fix:** Remove fake OS window buttons in favor of an email preview header (e.g., an authentic email client subject/recipient header); diversify workflow layout.

14. **[R-11] Pill-Shape Border Radius Inconsistencies**
    - **Location:** `css/theme.css:L515, L526`, `css/studio.css:L28`
    - **Reason:** Tags and preset chips use `border-radius: 999px` while surrounding inputs and buttons use `7px - 12px`, creating conflicting geometric languages.
    - **Recommended Fix:** Standardize chip corners to a deliberate 6px or 8px system radius matching inputs and buttons.

15. **[R-04] Generic Glyph Repetition (`verified`, `check_circle`)**
    - **Location:** `index.html:L26, L34-36, L53, L59`
    - **Reason:** Repetitive use of `check_circle` on all trust bullets and `verified` badges without tailored semantic meaning.
    - **Recommended Fix:** Use specific, meaningful iconography or remove decorative bullet icons for clean typographic hierarchy.

16. **[R-37 & R-31] Absence of `DESIGN.md` & Intentionality Dials**
    - **Location:** Project root
    - **Reason:** No `DESIGN.md` exists to document the product's identity, visual language, or three required antislop dials (ENERGY 1 / RHYTHM 1 / MOTION 1).
    - **Recommended Fix:** Create `DESIGN.md` defining typography rationale, color palette tokens, purpose statements, and dial settings.
